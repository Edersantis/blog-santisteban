Claude sirve para quitar trabajo repetido: resumir, clasificar, redactar el primer borrador, preparar el expediente antes de una reunión. El error es pedirle que cierre. Cerrar es decir sí o no con el nombre de alguien debajo.

Un flujo sano tiene una frontera visible. Hasta aquí prepara la máquina. Desde aquí decide una persona. Si esa línea no está escrita, el equipo no sabe qué está revisando y termina aprobando por cansancio.

Lo he visto en operaciones que conectaron tres herramientas en una tarde y llamaron a eso un sistema. Al mes, nadie podía explicar por qué un cliente había recibido un mensaje. El flujo era rápido. El criterio, invisible.

## La lista que cabe en una nota

Antes de automatizar un paso, hay tres preguntas. Si no se pueden responder, el flujo no sale del experimento.

```text
Antes de automatizar:
1. Qué decisión toma este paso.
2. Quién la revisa.
3. Qué pasa si el modelo se equivoca.
```

La tercera es la que casi nadie escribe. Un resumen mal hecho se corrige. Un correo enviado al cliente equivocado, no. El costo del error define cuánta autonomía se le puede dar al paso.

## Dónde sí ahorra

Preparar una reunión. Clasificar lo que ya llegó. Dejar el primer borrador de un documento cuyo argumento ya existe. Ahí Claude devuelve horas sin tocar la decisión.

> Automatizar un criterio que nadie puede explicar solo esconde el problema dentro de un paso más rápido.

El equipo que saca provecho no es el que tiene más flujos. Es el que puede señalar, en cada uno, dónde termina la máquina. Esa frontera se revisa. No se configura una vez y se olvida.

La velocidad importa. Importa después de saber qué no se puede delegar. El resto es una demo con más cables.
